# Contributing to DotFetch

First off, thanks for taking the time to contribute! 🎉

DotFetch is a community-driven project, and we love receiving contributions. Whether you're fixing a bug, improving the docs, or proposing a new feature, your help is appreciated.

## 🛠️ Development Setup

To start working on DotFetch locally:

1.  **Fork and Clone** the repository:
    ```bash
    git clone https://github.com/FreeRave/DotFetch.git
    cd dotfetch
    ```

2.  **Install Dependencies**:
    ```bash
    npm install
    ```

3.  **Run in Debug Mode**:
    * Open the project in VS Code.
    * Press `F5` to start debugging. This will compile the code and open a new "Extension Development Host" window.

4.  **Watch Mode** (Optional):
    * If you want to compile automatically on save without debugging:
    ```bash
    npm run watch
    ```

## 🐛 Found a Bug?

If you find a bug in the source code, you can help us by [submitting an issue](https://github.com/FreeRave/DotFetch/issues) to our GitHub Repository. Even better, you can submit a Pull Request with a fix.

## 💡 Feature Requests

If you have an idea for a new feature:
1.  Check existing issues to verify it hasn't been requested.
2.  Open a new issue describing the feature and why it would be useful.

## 📥 Submitting a Pull Request (PR)

1.  Fork the repo and create your branch from `main`.
2.  If you've added code that should be tested, add tests.
3.  Ensure the test suite passes (`npm test`).
4.  Make sure your code lints (`npm run lint`).
5.  Issue that Pull Request!

## 📜 Style Guide

* We use **TypeScript** for all logic.
* We follow the standard VS Code Extension guidelines.
* Please ensure **ESLint** checks pass before submitting.
